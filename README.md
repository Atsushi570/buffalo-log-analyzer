# Buffalo ログ解析ツール

Buffalo AirStation（WSR シリーズ等）のログファイルを読み込み、**イベントの頻度・異常が起きた時間帯・DHCP や Wi-Fi の不安定さ**を可視化してトラブルシュートに使うためのツールです。

**🔗 https://atsushi570.github.io/buffalo-log-analyzer/**

ログの解析はすべてブラウザ内（JavaScript）で行われ、**ファイルはどこにもアップロードされません**。現場のログをそのまま投入できます。

## 使い方

1. 上記 URL を開く
2. AirStation の設定画面から保存したログファイルをドラッグ＆ドロップ
   （まず動きを見たい場合は「サンプルログで試す」ボタン）
3. 診断サマリを上から読む

開いた直後は、**深刻なイベントが最も集中している日**に範囲と粒度を自動で合わせます。数ヶ月分のログを全期間・細かい粒度で表示すると、肝心の障害区間が数ピクセルに潰れて読めなくなるためです。全体を見たいときは「期間」を「全期間」に切り替えてください。

AP 機とルーター機のログを**まとめて投入**すると、同一時間軸で並べて比較できます。「AP が暴れている時刻にルーター側は何を出していたか」が突き合わせられるため、原因が個々の機器か上位側かの切り分けに使えます。

## 何がわかるか

### 診断サマリ
ログから読み取れる異常を、深刻度順に日本語で提示します。単なる件数の羅列ではなく「何が起きているか」「次に何を確認すべきか」まで出します。

| 検出項目 | 判定の根拠 |
|---|---|
| DHCP リースが保持できていない | `bound to ... renewal in N seconds` の N に対し、実際の再取得が極端に早い（25%未満）ものを数える |
| NTP の名前解決が繰り返し失敗 | `Unknown host` の回数。DNS 到達不能＝上位との通信が切れていた時間帯の代理指標 |
| 機器の再起動 | `BOOT` 行の検出 |
| 有線リンクの断 | `Link Status Changed - PortN Link DOWN` をポート別に集計 |
| IP プールの枯渇 | `Unable to pick client address` |
| Wi-Fi 認証の失敗／再接続の繰り返し | 認証失敗の回数、および同一 MAC が 5 分以内に再認証した回数 |
| DHCP の IP 拒否（NAK） | リース情報の不整合や IP 競合で発生 |
| ARPING エラー | IP 重複確認の失敗＝IP 競合の兆候 |
| イベントが集中している時間帯 | 中央値 + 4×MAD を超える区間（下記参照） |

### グラフ
- **イベント発生の推移** — 種別（DHCP / Wi-Fi / NTP / 有線 / システム）ごとの積み上げ。異常な時間帯は赤い帯で示す
- **機器ごとの比較** — 複数ログを同一時間軸で重ねる
- **曜日・時刻ごとの傾向** — 「毎朝この時間に落ちる」といった周期性の確認

### 表
- **イベント頻度** — 種別ごとの件数と初出・最終時刻
- **子機ごと** — 端末名・**IP アドレス**・MAC アドレス別の認証／IP 要求回数。特定端末が原因かの切り分けや、ルーターのリース一覧との突き合わせに使う
- **異常の時間帯** — 突出していた区間と、その時間帯の主なイベント

さらに、気になった時間帯の**生ログをそのまま確認**できます。

### 子機の IP アドレスについて

IP は DHCP サーバ側（`DHCPS`）のログにしか出ません。Wi-Fi 認証のログ（`AUTH`）は MAC アドレスだけを記録するため、AP 機のログ単体では IP が判明しません。

そこで、**同じ MAC を手がかりに複数のログを横断して IP を解決**します。AP 機のログだけを表示していても、同時に読み込んだルーター機の DHCP 記録から IP を補完します（補完した IP はマウスオーバーでその旨を表示）。

- IP が `—` の子機は、読み込んだどのログにも DHCP 記録が無い端末です（別の DHCP サーバから配られている、または IP 固定など）
- 期間中に IP が変わった子機には `2個` のようなバッジが付きます。リースが維持できていない兆候なので、マウスオーバーで履歴を確認できます
- 灰色の IP は `OFFER` / `REQUEST` のみで、`ACK` による確定を確認できていないものです

## 異常検出の考え方

異常時間帯の判定には、平均＋標準偏差ではなく**中央値 + 4×MAD**（中央絶対偏差）を使っています。平均と標準偏差は異常値そのものに引っ張られるため、大きな障害が 1 件あるとしきい値が跳ね上がり、かえって検出漏れを起こします。

また、平常時の基準値は**イベントが 1 件以上あった区間だけ**から取ります。何も起きていない夜間の空区間を含めて中央値を取ると基準が 0 に張り付き、「平常の 300 倍」のような無意味に誇張された数字になるためです。

## 対応しているログ形式

```
YYYY/MM/DD HH:MM:SS<空白>CATEGORY<TAB>メッセージ
```

カテゴリは `DHCPC` / `DHCPS` / `AUTH` / `NTP` / `WIRED` / `SYSTEM` / `BOOT` に対応。付属のサンプル 2 ファイル（6,413 行）は**解析できない行 0 件**で全行分類されます。

未知のメッセージも「◯◯ その他」として件数に含まれるため、取りこぼしは起きません。画面下部に解析できなかった行数が常に表示されます。

### 時刻同期前のログについて
AirStation は NTP 同期前のログを `2025/01/01 00:00:00` として記録します。これを時間軸に含めると数年分の空白ができてしまうため、集計対象から除外し、除外件数を画面に表示しています（再起動の検出自体は行います）。

## ローカルで動かす

ES モジュールを使っているため、`file://` で直接開くのではなく簡易サーバー経由で開いてください。

```bash
git clone https://github.com/Atsushi570/buffalo-log-analyzer.git
cd buffalo-log-analyzer
python3 -m http.server 8000
# http://localhost:8000 を開く
```

## 構成

ビルド不要・依存パッケージなしの静的サイトです。グラフは SVG を直接組み立てています。

```
index.html        画面の構造
sample/           デモ用の匿名化済みログ
styles.css        配色とレイアウト（ライト／ダーク両対応）
src/parser.js     ログのパースとイベント分類
src/analyze.js    集計・異常検出・診断ロジック
src/charts.js     SVG グラフ描画
src/app.js        画面の組み立てとイベント配線
```

## サンプルログについて

`sample/` に置いてあるログは、実際に DHCP が不安定になった現場のログを匿名化したものです。MAC アドレス・端末名・IPv6 アドレスは置換済みで、障害の再現性（時刻・件数・イベントの並び）はそのまま保っています。

なお、解析対象の実ログは `logs/` に置いても Git の追跡対象外（`.gitignore`）です。MAC アドレスや端末名を含むログが誤って公開されるのを防ぐためです。

Buffalo AirStation のログを読み込んで、イベントの頻度・異常が起きた時間帯・DHCPやWi-Fiの不安定さを可視化するツールを作りました。ブラウザだけで動きます。

**🔗 https://atsushi570.github.io/buffalo-log-analyzer/**
**📦 https://github.com/Atsushi570/buffalo-log-analyzer**

## 作った理由

Wi-FiとDHCPが不安定なとき、AirStation の設定画面からログは落とせます。ただ、出てくるのは数千行のテキストです。

```
2026/09/03 04:03:36      DHCPC	 DHCPRELEASE on br0 to 192.168.0.1 port 67
2026/09/03 04:04:31      DHCPC	 bound to 192.168.0.16 -- renewal in 86378 seconds.
2026/09/03 04:05:19      DHCPC	 DHCPRELEASE on br0 to 192.168.0.1 port 67
2026/09/03 04:06:14      DHCPC	 bound to 192.168.0.16 -- renewal in 86368 seconds.
```

「なんとなく朝方が怪しい」という体感はあっても、grepと目視で追うのは辛い。時間帯ごとの傾向と、平常時との差が見たかったので作りました。

## できること

### 診断サマリ

ログから読み取れる異常を、深刻度順に日本語で出します。件数の羅列ではなく「何が起きているか」と「次に何を確認すべきか」まで出すようにしました。

![診断サマリ](/images/buffalo-log-analyzer/01-diagnosis.png)

検出しているのはこのあたりです。

- IPの解放と再取得の繰り返し（DHCPリースの異常）
- NTPの名前解決の失敗
- 機器の再起動
- 有線リンクの断（ポート別）
- IPプールの枯渇
- Wi-Fi認証の失敗、短時間の再認証の繰り返し
- DHCPのIP拒否（NAK）、ARPINGエラー
- イベントが平常時より突出している時間帯

### グラフ

種別ごとの内訳を時系列で並べます。赤い帯が「平常時と比べて突出している時間帯」です。

![推移](/images/buffalo-log-analyzer/03-allperiod.png)

上の画像は56日分。7〜8月は平常で、9/2〜9/3だけ突出しているのが一目で分かります。

複数のログをまとめて投入すると、**同一時間軸で機器ごとに比較**できます。同時刻に両方の機器で異常が出ていれば、原因は個々の機器ではなく上位側というふうに切り分けられます。

![機器ごとの比較](/images/buffalo-log-analyzer/02-charts.png)

曜日×時刻のヒートマップもあるので、「毎朝この時間に落ちる」といった周期性も確認できます。

### 子機ごとの表

端末名・IPアドレス・MACアドレス別に、認証回数やIP要求回数を並べます。特定の端末が原因かを切り分けるのに使います。

![子機ごと](/images/buffalo-log-analyzer/04-clients.png)

IPは DHCPサーバ側（`DHCPS`）のログにしか出ません。Wi-Fi認証のログ（`AUTH`）はMACアドレスだけを記録するため、AP機のログ単体ではIPが分かりません。そこで**同じMACを手がかりに複数のログを横断してIPを解決**しています。AP機のログだけを表示していても、一緒に読み込んだルーター機のDHCP記録からIPを補完します。

### 生ログの確認

気になった時間帯を選ぶと、その前後の生ログをそのまま読めます。診断結果は出発点なので、最後は自分の目でログを見るためのものです。

## 実装

ビルド不要・依存パッケージなしの静的サイトです。全体で約2,100行。

```
index.html        画面の構造
styles.css        配色とレイアウト（ライト/ダーク両対応）
src/parser.js     ログのパースとイベント分類
src/analyze.js    集計・異常検出・診断ロジック
src/charts.js     SVGグラフ描画
src/app.js        画面の組み立て
```

### 解析はすべてブラウザ内

現場のログにはMACアドレス・端末名・内部IPが含まれます。サーバーに送るツールにすると、それだけで業務で気軽に使えなくなるので、`FileReader` で読んでブラウザ内で処理しています。アップロードは一切ありません。

そのおかげでGitHub Pagesにそのまま置けます。

### グラフはSVGを直接組み立て

Chart.js なども使わず、SVG要素を手で作っています。棒グラフ・折れ線・ヒートマップくらいならこの程度で済みます。

```js
function el(name, attrs = {}) {
  const n = document.createElementNS('http://www.w3.org/2000/svg', name);
  for (const [k, v] of Object.entries(attrs)) n.setAttribute(k, v);
  return n;
}
```

CDNへの依存が無くなるので、単一の静的サイトとして完結します。ホバー時のツールチップとクロスヘアも自前ですが、`pointermove` で最近傍のビンを拾うだけなので大した量ではありません。

### イベント分類は定義の配列で持つ

ログのメッセージは正規表現で分類し、種別・深刻度・抽出するフィールドをまとめて定義しています。

```js
{ id: 'dhcpc_bound', cat: 'DHCPC', label: 'IP取得完了 (bound)',
  kind: 'dhcp', severity: 'info',
  re: /^bound to (\S+) -- renewal in (\d+) seconds/,
  fields: m => ({ ip: m[1], renewal: +m[2] }) },
```

新しいログ形式に対応したいときは、この配列に1つ足すだけです。未知のメッセージも「◯◯ その他」として件数に入るので、取りこぼしは起きません。付属のサンプル2ファイル（6,413行）は解析できない行0件で全行分類されます。

### 異常検出は中央値+MAD

「イベントが突出している時間帯」の判定には、平均+標準偏差ではなく**中央値+4×MAD**（中央絶対偏差）を使っています。平均と標準偏差は異常値そのものに引っ張られるため、大きな障害が1件あるとしきい値が跳ね上がり、かえって検出漏れを起こします。

```js
const active = vals.filter(v => v > 0);   // 空ビンを除く
const med = median(active);
const mad = median(active.map(v => Math.abs(v - med))) || 1;
const threshold = Math.max(med + k * mad, minCount);
```

平常時の基準を「イベントが1件以上あった区間だけ」から取っているのもポイントです。何も起きていない夜間の空区間を含めて中央値を取ると基準が0に張り付き、「平常の300倍」みたいな無意味な数字になります。

### 開いた瞬間に問題の日を出す

数ヶ月分のログを全期間・1時間粒度で表示すると、肝心の障害区間が数ピクセルに潰れて読めません。なので初期表示では、**深刻なイベントが最も集中している日**に範囲と粒度を自動で合わせています。

```js
function pickBucket(days) {
  if (days <= 1.5) return 1800_000;    // 30分
  if (days <= 4) return 3600_000;      // 1時間
  if (days <= 21) return 21600_000;    // 6時間
  return 86400_000;                    // 1日
}
```

## 使い方

サイトを開いてログをドラッグ&ドロップするだけです。まず動きを見たい場合は「サンプルログで試す」ボタンから、匿名化した実際の障害ログを読み込めます。

複数ファイルをまとめて投入すると機器間の比較ができるので、AP機とルーター機のログが両方あるなら一緒に入れるのがおすすめです。

## おわりに

作ってみて分かったのは、大変なのはパーサではなく**そのログメッセージが本当は何を意味するのか**の確認だったことです。DHCPサーバのログは、正常動作でも `Error` や `Unable` を含むメッセージを普通に出します。文面だけで重み付けすると、正常なネットワークを「重大な障害」と報告するツールになってしまいます。

そのあたりの判定根拠はREADMEに書いてあります。Buffalo以外のログにも `src/parser.js` に定義を足せば対応できるので、よければ試してみてください。
